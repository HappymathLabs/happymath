# Decision 文档阅读指南

本目录是 HappyMath Decision 模块（多准则决策 MCDM 统一框架）的完整使用说明。编写 Decision 相关代码前，必须先阅读完本目录下所有文档，避免把主观/客观赋权、评分排序、两两比较和模糊决策等不同方法的使用前提和输入格式混在一起。

## 推荐阅读顺序

1. `README.md`

   先读本文件，了解文档结构、阅读顺序和编码前置要求。

2. `quickstart.md`

   快速建立正确的工作流：理解七类决策类的定位、统一的"实例化 → `decide()` → 获取结果"三步使用模式、关键参数含义以及使用注意与已知缺陷。这是日常使用 Decision 模块时最先参考的文件。

3. `api.md`

   系统阅读每个类和接口的参数、设计思想、返回形式和结果结构。尤其要读完 `decide()` 的参数要求以及 `get_weights()`、`get_scores()`、`get_rankings()`、`get_executed_methods()` 的适用类别。

4. `examples.md`

   查看按方法类别组织的完整示例，覆盖主观赋权、客观赋权、评分排序、两两比较和模糊决策的完整工作流（如 Entropy + TOPSIS 组合）。

## 每个文件的含义

| 文件 | 作用 |

## 编写代码前必须确认

- 已阅读本目录下全部文档，而不是只复制某个示例片段。
- 已明确当前任务类型：主观赋权、客观赋权、评分排序、两两比较还是模糊决策，并据此选择对应的类。
- 已确认决策矩阵 `dataset` 的形状为 `(n_alternatives, n_criteria)`，`criterion_type` 长度为 `n_criteria` 且只含 `'max'` / `'min'`。
- 已确认权重和接近 `1.0`，否则会触发 `UserWarning`。
- 已明确是否需要通过 `methods` 参数限定运行方法；不指定时框架会运行所有"参数够用"的方法，模糊方法可能显著变慢。
- 已确认所选方法的专属参数齐全，例如 `spotis` 需要 `s_min`/`s_max`，Pairwise 类的 `P`、`Q`、`V`、`S`、`F` 长度必须等于准则数。
- 已确认模糊方法的 `dataset` 为三维数组 `(alternatives, criteria, 3)`，每个元素为三角模糊数 `(l, m, u)`。
- 已注意 `decide()` 内部以 `try/except` 包装各方法，失败只发警告不中断，调用后必须检查 `get_executed_methods()` 确认目标方法确实成功。
- 运行示例或测试时使用 conda 的 `happymath` 环境。
